# 画面デモとバックエンド接続のガイド

HTML・CSSと画面操作を確認するためのプロトタイプです。Java／Spring Boot・MySQL・認証・API通信は未実装です。
既存のExpressはHTMLと静的ファイルを配信するためだけに使っています。

## 起動と確認

```sh
cd /workspace/studyrecord
npm run dev
```

ポート3000で起動します。計測画面を開き、左のナビゲーションで振り返り・分野管理へ移動します。
ログイン画面の見本はヘッダーの「ログイン画面を見る」から開けます。
これは認証画面の外観とフォームの見本です。送信ボタンは認証せずデモへ移動するだけで、入力値をサーバーに送信・保存しません。

### 確認できるもの

- ストップウォッチの開始・終了、同じページ内での画面切り替え中の計測継続。
- 記録入力モーダルの手動追加・編集・破棄、入力行の追加・削除、同じ分野の複数行入力。
- 必須項目、整数の時間・分、1分以上、合計24時間以内、メモの上限、学習日の入力チェック。
- 入力合計の自動計算、計測時間との差の注意表示。
- 日別詳細からの記録確認・編集・削除、カレンダーの前月・翌月表示。
- 分野の追加・名前変更・削除、大文字・小文字を区別しない重複チェック、使用中分野の削除拒否。
- 記録変更後の累計・分野別・日別集計の更新。

## デモの制限

- サンプルデータは日本時間の今日を基準に生成します。集計も画面確認用にJavaScriptで計算しています。
- データと計測状態はメモリ内のみです。再読み込みでデータは初期状態に戻り、計測と未保存入力も失われます。
- localStorageの復元、複数タブ同期、ユーザー認証、実際のDB保存、通信エラーの再現は含めません。
- 「今日の積み重ね」「最近の学習記録」、計測画面からの手動追加はレイアウトを確認するための追加案です。2週間版の必須機能への追加を意味しません。
- PC向けに確認しています。狭い表示幅向けの最低限のCSSはありますが、スマホ実機の動作保証は今回の対象外です。
- 画面URLは仮に `/#timer`、`/#review`、`/#subjects` としています。設計案の `/review` などのURLの採用は未確定です。
- 記録入力中に新しい分野が必要な場合は、現時点では破棄して分野管理で追加し直します。入力保持付きの分野追加は未実装です。
- 既存の `public/js/dom.js`、`state.js`、`handler.js`、`render.js`、`rendertime.js` は残していますが、新しい画面からは読み込みません。

## Spring Bootへの接続で学ぶ箇所

1. HTML・CSS・JavaScriptをSpring Bootの静的配信へ移します。現在のEJSには動的埋め込みがないため、アプリ画面はHTMLとして利用できます。
2. ログイン画面をThymeleafのテンプレートにし、仮のlogin-demo.jsを外します。フォーム送信先をSpring Securityの `/login` にし、CSRFトークンとログインエラーを接続します。
3. `GET /api/me` で認証ユーザーを取得し、固定のstudy_user表示を置き換えます。デモの「ログイン画面を見る」は実際のログアウト操作に置き換えます。
4. demo-store.jsへの操作を、設計済みのAPIを呼ぶ層へ置き換えます。デモは同期関数なので、呼び出し元もasync/awaitと読み込み・失敗状態に対応する必要があります。
5. 状態を変えるリクエストにはCSRFトークンを渡します。UIだけの入力チェックを信用せず、サーバーでも検証・所有者確認を行います。

| 現在の呼び出し・表示 | 接続するAPI |
|---|---|
| saveRecord（新規） | POST /api/study-records |
| saveRecord（編集） | PUT /api/study-records/{id} |
| deleteRecord | DELETE /api/study-records/{id} |
| 日別の記録詳細 | GET /api/study-records?date=... |
| 編集対象の取得 | GET /api/study-records/{id} |
| listSubjects | GET /api/subjects |
| saveSubject・deleteSubject | 分野のPOST・PUT・DELETE |
| 累計・分野別 | GET /api/stats/summary |
| カレンダー | GET /api/stats/calendar?month=... |

`listRecords()` はデモが全サンプルを持つための関数で、設計済みAPIには全記録を無条件に取得する入口はありません。
実際には日別・月別・集計APIから必要な表示を読み込みます。「最近の学習記録」「今日の積み重ね」を採用する場合の取得方法は別途決めます。

### 入力項目とJSON

- 日付入力のnameは `studyDate`。
- 各行の分野は `subjectId`、メモは `memo`。
- `hours` と `minutes` を `hours * 60 + minutes` で `durationMinutes` に変換します。
- 計測時だけ `startedAt`・`endedAt` を付け、手動追加ではnullにします。
- デモの保存関数はメモリ内の共通モデルを受け取りますが、実APIのPUTでは計測日時を送らず、日付と明細だけを送る仕様です。
- 所有ユーザーIDや合計時間は保存リクエストに含めません。
