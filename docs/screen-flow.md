# 学習記録アプリ 画面遷移図

全体の完成像に対する画面遷移です。2週間版への切り分けは別途行います。
既存の決定を基にしていますが、画面のURLと分野管理を独立画面にする構成は提案です。アプリには未実装です。

## 主な画面の移動

```mermaid
flowchart TD
    Entry[アプリにアクセス] --> Auth{ログイン済みか}
    Auth -->|いいえ| Login[ログイン画面]
    Auth -->|はい| Timer[計測画面]
    Login -->|ログイン成功| Timer
    Login -->|失敗・エラー表示| Login

    Timer <-->|ナビゲーション| Review[振り返り画面]
    Timer <-->|ナビゲーション| Subjects[分野管理画面・提案]
    Review <-->|ナビゲーション| Subjects

    Timer -->|ログアウト| Logout{計測中なら破棄確認}
    Review -->|ログアウト| Logout
    Subjects -->|ログアウト| Logout
    Logout -->|計測なし・または確認して実行| Login
    Logout -->|確認を取り消す| Back[元の画面へ戻る・計測継続]
```

- ログイン成功後、最初に表示するのは計測画面です。
- 振り返り画面には累計時間・分野別時間・カレンダーをまとめます。
- 分野管理画面には分野の一覧・追加・名前変更・削除をまとめる案です。管理操作の配置は未確定です。
- 全体仕様ではアプリ内の画面移動でも計測を継続します。
- 未認証・セッション切れの場合はログイン画面へ案内します。入力中の場合は、画面移動で未保存内容が失われることを伝えます。
- 記録入力モーダルを開いている間は背後の画面を操作しません。先に記録・更新または破棄を済ませます。

## 計測から記録する流れ

```mermaid
flowchart TD
    Ready[計測画面・開始前] -->|開始| Running[計測中]
    Running -->|終了・時間確定| Input[記録入力モーダル]
    Input -->|記録する| Save{入力検証・保存}
    Save -->|成功| Ready
    Save -->|入力エラー・保存失敗| Input
    Input -->|破棄する| Discard{破棄の確認}
    Discard -->|破棄を確定| Ready
    Discard -->|取り消す| Input
```

- 記録入力は別ページへの移動ではなく、計測画面の上でモーダルを開きます。
- 成功時はモーダルを閉じ、次の計測を始められる状態に戻します。入力失敗時は内容を残します。
- 「閉じる」や背景クリックでは入力モーダルを閉じません。
- 通信切断で結果が不明な場合は保存失敗と断定せず、結果を確認できないことを表示します。結果確認へ進む際の入力保持などの詳細は別途決めます。

## カレンダーから記録を確認・追加・編集・削除する流れ

```mermaid
flowchart TD
    Review[振り返り画面] -->|カレンダーの日付を選択| Daily[日別の記録詳細モーダル]
    Daily -->|閉じる| Review
    Daily -->|記録を追加| Add[記録入力モーダル・新規]
    Daily -->|編集| Edit[記録入力モーダル・編集]
    Daily -->|削除| Delete{削除確認}

    Add -->|記録する| Create{入力検証・保存}
    Create -->|成功・表示を再取得| Daily
    Create -->|失敗・入力保持| Add
    Add -->|確認後に破棄| Daily

    Edit -->|更新する| Update{入力検証・更新}
    Update -->|成功・表示を再取得| Daily
    Update -->|失敗・入力保持| Edit
    Edit -->|確認後に変更を破棄| Daily

    Delete -->|削除を確定| Request{削除API}
    Delete -->|取り消す| Daily
    Request -->|成功・表示を再取得| Daily
    Request -->|失敗・エラー表示| Daily
```

- 日別の詳細は閲覧用で「閉じる」があります。入力モーダルの2択とは別です。
- 記録がない日も日別詳細を開き、手動追加できます。
- 追加・編集時はいったん日別詳細を隠し、入力モーダルを表示する案です。モーダルを重ねて操作しない構成にします。
- 追加・更新・削除後に日別詳細へ戻る構成は提案です。表示中の日付を維持して再取得し、学習日を変更した場合は移動先の日付を案内します。カレンダーと集計も更新します。
- 手動追加の初期日は、決定済みの方針どおり「今日」です。カレンダーで選択した日を初期値に変更するかは未決定です。
- 入力の破棄確認を取り消した場合は、そのまま入力を続けます。

## 画面のURL案

| 画面 | メソッド・URL案 | 状態 |
|---|---|---|
| ログイン | GET /login | 決定済み |
| 計測 | GET / | 提案 |
| 振り返り | GET /review | 提案 |
| 分野管理 | GET /subjects | 提案 |

モーダルには独立した画面URLを設けない案です。データは設計済みの `/api/...` から取得します。
ログイン送信は `POST /login`、ログアウトは `POST /logout` で行います。ログアウトをGETのリンクで実行しません。

## 図の読み方

- 四角：画面、表示状態、モーダル。
- ひし形：確認・成功と失敗などの分岐。
- 矢印の文字：移動のきっかけとなる操作や結果。
- モーダルへの矢印は、ページ遷移ではなく表示の切り替えを表します。

細かな配置や装飾はこの図の対象外です。全体の設計方針は [design-notes.md](design-notes.md) を参照してください。
